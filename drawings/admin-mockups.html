Camp Shower — Admin page layout explorations

Three ways to re-organize the phone-hosted admin dashboard served from the Tough at /. Each phone below is scrollable and lightly interactive (tabs, accordions, tiles) so you can feel how much scrolling each layout actually needs. All three use the same fake data: 14 members, 58 showers, 412.6 gal total.

What's hard about the current page

  • Ten equal-weight cards in one column. Enrolling a wristband (the most common job) sits next to "change password" (done once). Reaching "Recent showers" or "Reboot" means scrolling past the speaker and knob sections every time.
  • Health is one run-on sentence ("Uptime 192 min · heap 118k free (low-water 96k) · WiFi clients 1 · hub ok · relay ok · …"). You have to read the whole line to find the thing that's DOWN.
  • Member editing uses three browser prompt()/confirm() dialogs in a row (name → limit → enabled). Easy to mis-tap, no way to see the current value while typing, and iOS Safari renders them badly.
  • No "what's happening right now." The status banner is text-only; there's no glanceable live state (showering / enrolling / idle) or total-gallons hero number.
  • Per-member gallons vs. limit is only shown as the button label "Edit · 10.0 gal limit".

Fixes shared by all three layouts

  • A sticky header with the live status banner and a row of health pills (Hub · Relay · RFID · SD · Speaker · uptime) — green dot / red dot, so a fault is visible from anywhere on the page.
  • Inline member editor: tap a member row, it expands to name / limit / enabled toggle / Save / Delete. No browser dialogs.
  • Members show avatar initial, gallons, shower count, and limit chip; disabled members get an amber avatar instead of a "disabled" word.
  • Recent showers use end-reason chips (BUTTON / LIMIT / TIMEOUT / HANDOFF / REBOOT) with color so limit hits and timeouts jump out.
  • Still a single PROGMEM string, no external fonts or assets, ~same JS size — the same /api/overview poll drives everything.

A · Tabbed command center

One sticky header (status + health) and four tabs: Members · Showers · Station · Audio. Each tab is roughly one phone screen tall, so there's essentially no scrolling. The first tab is the one you use most. Same dark teal palette as today, just tightened up.

Trade-offs

  • Zero-scroll for the common tasks; each tab is a focused workspace.
  • Health pills in the header mean you never lose the station's state while on the Audio tab.
  • Info in other tabs is hidden — you can't see "last shower" while enrolling. The header banner mitigates this for live state.
  • Needs ~15 lines of JS for tab switching (trivial, but it's new code on the ESP32 page).

B · Overview + fold-out sections

Still one page, but ordered by how often you use it and with progressive disclosure. Stat tiles and the members list are always open; calibration, audio, knob, controller, and password are collapsed <details> rows whose summary line shows their live state ("Speaker — connected · idle · 60 %"). So everything is glanceable without scrolling, and controls appear only when you open them. Native HTML, no JS routing.

Trade-offs

  • Everything visible at a glance in ~1.5 screens; the accordions collapse 60 % of today's page height.
  • Smallest change to the firmware: same DOM structure, wrapped in <details>, plus the tiles and inline editor.
  • Scales to a laptop nicely as a two-column grid (wide frame above).
  • Members list still grows with camp size; at 30+ members it will need a search box or "show all" fold.
  • Open accordions push content below them down — fine on a phone, slightly jumpy.

C · Home screen + focused sub-pages (light "daylight" look)

Treats the admin page like a small phone app. A home screen shows one big "Enroll wristband" button (the #1 task) and six tiles that are both status readouts and navigation — tap Water to get the showers log, tap Speaker to get the audio controls. Also explores a cream/teal/orange light theme, which is far easier to read on a phone in playa daylight than the dark green.

Trade-offs

  • Home screen never scrolls; every number that matters fits above the fold. Sub-pages are single-purpose and short.
  • Light theme is the most legible outdoors; the orange CTA is unmissable.
  • Two taps for anything that isn't enrolling. Calibration and knob setup involve going back and forth to check readings (the sub-page shows live values, so this is mostly fine).
  • Slightly more JS (view switching + back button) and a bigger CSS block — still a few KB, fine for PROGMEM.
  • Light theme at night on a phone is bright; could honor prefers-color-scheme and ship both.

Recommendation

Go with B as the structure — it fixes the scrolling and readability with the least new code and stays one page — and borrow the light "daylight" palette from C if you're often on the page mid-day (or ship both via prefers-color-scheme). If you find yourself wanting even less on screen, B upgrades to A cheaply: the fold-out sections become tabs and the header stays the same.
